## D-006  [SSH FIXES, v0.3.1] SSH devices connect from the hub's ~/.ssh/config aliases with no setup; four bugs in the v0.3 SSH path fixed; first real SSH run against computenode-01 and guru   [user: "the ssh setup is buggy"; aliases: robot -> guru, rudra -> rudy-windows, rudy8k later]  2026-10-25

1. ALIASES INSTEAD OF A FORM (`cmgr/sshconfig.py`). The hub lists the non-wildcard `Host` names in `~/.ssh/config` (following `Include`), resolves each with `ssh -G` (so Match/Include/defaults apply exactly as ssh applies them), and matches the resulting hostname to a Tailscale device by label, MagicDNS name or IP (or by resolving it to the device's IP). Matched devices are reached with `ssh <alias>` and switched on by default. A machine running `cm` still takes precedence; an explicit SSH target typed in the panel wins over the alias. On this PC the config gave server -> computenode-01, thinkpad -> rudy8k, robot -> guru (`pi` is a LAN address and matched nothing). The default Python is `python` for Windows devices, `python3` elsewhere.
2. BUG: typing in the SSH form was wiped. The 4 s state refresh re-rendered the devices panel and reset the inputs and focus. Now the panel is not redrawn while focus is inside it, and unsaved text is kept per device and field. Verified headless: text typed into the field survived 9 s of refreshes. Enter in a field submits.
3. BUG: one slow device froze the page. `state()` waited for every device; a first SSH connect plus snapshot can take ~45 s. Now each device refreshes in its own background task; `state()` waits at most 6 s, then returns that device's last known data (or "connecting…") while the refresh continues. Test: a device blocked for 10 s; `snapshots()` returned in under 3 s with "connecting…", then "ok" once it finished.
4. BUG: wrong or missing tmux over SSH. A non-interactive SSH login does not load conda, and computenode's tmux is `~/miniforge3/bin/tmux`. The agent now uses the executable of the user's running tmux server (`/proc/<pid>/exe`), falling back to PATH and common install folders. Simulated in WSL: a server started from an off-PATH copy was found with PATH=/usr/bin:/bin. Real: over `ssh server`, computenode reported tmux=/home_local/rudra_1/miniforge3/bin/tmux, tmux_ok.
5. BUG: two sessions in one folder could show each other's chat. "Follow the newest transcript after /clear" took the other live session's newer file (both openpi panes on computenode showed the same text). Files belonging to other live sessions with the same account and folder are now excluded. Test included.
6. PREVIEWS. Session cards now show the latest of: Claude's last text line, the tool it is running, or your last prompt, read from the last 256 KB of the transcript and cached by file size. The screen line is only a fallback, because it was mostly Claude Code tips ("Tip: Use /btw…", "/remote-control is active"). The rule above the input now carries the session name ("──── trnsfr ─"), so rule detection accepts a label. Markdown cleanup no longer strips underscores from paths.
7. UI: long prompt bubbles were squashed to a sliver because flex items in the column shrank; `flex-shrink: 0` fixes it.
8. FIRST REAL SSH RUN (read-only). From a test hub on rudy, using the existing keys and aliases, over `ssh server` and `ssh robot`: computenode-01 showed its 5 sessions with accounts and DECISIONS (trnsfr, noble_lift, flux_action_ur10, 2x openpi), guru was connected with no Claude sessions, and usage merged across machines with all four accounts. Over SSH the trnsfr chat (transcript 283 MB) loaded in 1.2 s, a poll for new messages took 0.3 s, the screen 63 ms, and DECISIONS.md (247 entries, latest D-251) 1.5 s. Nothing was sent to any session. The test hub was stopped afterwards and no ssh processes were left behind.
9. NOT VERIFIED. SSH into Windows (`ssh rudra`, psmux in an SSH logon session) and rudy8k (offline). 55 tests pass on Windows and WSL.

## D-005  [UI + TOPOLOGY, v0.3] Chat view from Claude Code's transcript; one hub reaches the other machines over SSH with nothing installed there; device and account switches; usage on the right   [user feedback: "a downgraded version of the terminal", "can't even scroll through the chat", "should be hosted on one device but show all sessions from all my devices", "control which devices and accounts", "usage on the right"]  2026-10-25

1. WHY THE SCREEN VIEW COULD NOT SCROLL. Measured on the EE6934 session: `#{alternate_on}` = 1 and `#{history_size}` = 0. Claude Code draws its UI in tmux's alternate screen, so tmux keeps no scrollback and `capture-pane -S -N` can never return more than one screen. The conversation exists only in Claude Code's transcript.
2. CHAT FROM THE TRANSCRIPT (`cmgr/transcript.py`, `/api/transcript`). The file is located from the session registry (account dir, cwd, sessionId); after `/clear` or a resume the newest `.jsonl` in that folder written since the process started wins. Kept: user prompts (slash commands as chips), assistant text, tool calls (name plus a one-line summary from command / file_path / pattern / ...), tool results (cut to 4000 chars). Dropped: thinking, isMeta, isSidechain, compact summaries, attachments, api-request blobs. The real file was 150 MB with 9,067 lines; reading the tail by byte range takes 20 ms. `before=` pages back (the reader's scroll position is kept), `since=` polls appended bytes, and a half-written last line is left for the next poll. The UI renders markdown (code fences, lists with one nesting level, tables as monospace, inline code / bold / italic / links), folds runs of more than 3 tool calls, and expands a tool on tap.
3. SCREEN TAB + WAITING CARD. The live screen stays as a second tab. When the screen status is "waiting", the chat shows the last 16 lines of the screen in a card above the key bar (1/2/3/Esc/Enter), so a permission prompt can be answered without switching tabs.
4. ONE HUB, SSH TO THE REST (`cmgr/remote.py`). For a device switched to SSH the hub runs `ssh -T -o BatchMode=yes -o StrictHostKeyChecking=accept-new <target> <python> -u -c "exec(input())"`. Line 1 on stdin installs an in-memory meta-path importer, line 2 is the package source as JSON, then requests and replies are JSON lines (ids matched, stray banner lines ignored). Nothing is written on the remote disk. Each device gets 2 channels so the 6 s snapshot cannot block the open session's chat or screen polling; a dead channel is restarted once. The bootstrap has no inner quotes because `exec(__import__('sys')...)` failed under PowerShell. Verified through bash -lc (WSL), cmd.exe and PowerShell with the command passed as one argument (how sshd runs it). If ssh exits at once, its last stderr line is reported (earlier "[Errno 32] Broken pipe", a bug found by a test). NOT verified: a real ssh hop. The only SSH server here is this PC's, and no key is set up for it; the attempt added `localhost` to `~/.ssh/known_hosts`.
5. DEVICES AND ACCOUNTS (`hub.json` on the hub). Devices = this machine + every computer of my Tailscale user (MagicDNS label as name, since hostnames repeat: two "rudy") + configured ones. Per device: enabled, via auto|ssh, ssh target, python. A machine running `cm` is used over HTTP automatically; otherwise it stays "not connected" until SSH is set up, and only enabled, online devices are polled. Hidden accounts filter the sessions list in the UI; their usage stays on the right, dimmed.
6. LAYOUT. Sessions grouped by device on the left, the session in the middle, usage in a right column (collapsible) at >= 1200 px and a right-hand drawer below that; one column at a time on phones.
7. TESTS. 50 pass on Windows and WSL Ubuntu 24.04. New: transcript parsing and byte-range reads (tail / before / since / half-written line / reset), the in-memory agent over a real pipe (errors keep their 4xx status, channel stays usable), the readable ssh failure, devices (unconfigured / offline / ssh / switched off, persisted settings), hidden accounts. The UI was driven headless at 390 px and 1500 px against the live EE6934 session: 13 items rendered, load-earlier added 7 more while keeping the position, no console errors.

## D-004  [FIX, v0.2.1] `cm up` replaces an older cm that still holds the port, and reports a failed start as a failure   [found on computenode-01 on the first `cm up` after the update]  2026-10-25

1. WHAT HAPPENED. On computenode-01 the `cm serve` started by hand under v0.1 was still running. The new server could bind neither 100.115.95.117:8765 nor 127.0.0.1:8765 and exited, yet `cm up` still printed "running in tmux session 'cm'".
2. FIX (`cmgr/ports.py`, `cm up`). Before starting, `cm up` lists the processes listening on the port (`ss -ltnp`, falling back to `lsof` on Linux; `netstat -ano` on Windows) and reads their command lines. A process whose command line is a cm server (`-m cmgr serve` or `cm serve`) is stopped with SIGTERM, or taskkill on Windows, and the stop is printed. Any other program is only reported, for example VS Code on 127.0.0.1:8765 on rudy, which is skipped by the bind logic of D-003. After starting, if the session's output has no "listening on" line, `cm up` kills the session, says "cm did NOT start", and exits 1. `cm doctor` shows who holds the port.
3. VERIFIED in WSL with real tmux: a hand-started server (pid 524) was stopped and the new one took over both addresses; with the only address blocked by another program, cm up exited 1 and left no session behind. 43 tests (new: cm-server recognition, ss / netstat parsing).

## D-003  [SETUP, v0.2] Zero configuration: Tailscale finds the machines and decides who may connect, Claude Code's own history supplies the projects, one command per machine (`cm up`); Remote Control used only as a deep link   [machines: rudy (Windows, psmux) + guru, computenode-01, rudy8k (Ubuntu); supersedes the token / peers / project_roots setup of D-001]  2026-10-25

1. TRIGGER (user feedback on the first deploy). The setup was too tedious: a token copied to every machine, peers listed by hand (the README example names `labpc` / `winbox` were copied literally and failed), and project folders listed by hand. On Windows `cm serve` crashed because VS Code already listens on 127.0.0.1:8765 (WinError 10013 after the Tailscale address had bound fine).
2. REMOTE CONTROL CONSIDERED, NOT USED AS TRANSPORT. Claude Code's Remote Control (claude.ai/code / Claude app) shows only the signed-in account's sessions. With 4+ accounts (one of them a Team account) that means switching accounts to find a session, with no cross-account usage view and no DECISIONS flow. There is no public API to list or drive sessions across accounts, and building on private claude.ai endpoints was rejected. Kept as a complement: the session registry carries `bridgeSessionId` when Remote Control is on, and the session view then shows a ☁ link to `https://claude.ai/code/<id>`.
3. DISCOVERY. Every `cm serve` is also a hub. It reads `tailscale status --json`, keeps the online peers whose UserID equals its own (machines shared in by other people, here `rujas` and `patrick`, are excluded; phones are skipped), probes `http://<ip>:<port>/api/info` on each, and adds the ones that answer. It re-checks every 60 s. Verified live from this PC: guru, john and computenode-01 found, rujas and patrick excluded. The port must be the same on every machine (default 8765).
4. AUTHORIZATION. (a) A configured token still works but is optional. (b) Remote callers are allowed when `tailscale whois` says their device belongs to my own Tailscale user (cached 5 min). (c) Connections from the machine itself (loopback or its own Tailscale IP) are allowed only with `trust_local`, which defaults to true on Windows/macOS and false on Linux, because computenode-01 is a shared server and its other users could otherwise connect locally. Verified with real whois data: all own machines and the phone ALLOW, rujas / patrick deny, own IP denied with trust_local off; in WSL a local request got 401 with the reason.
5. PROJECTS WITHOUT CONFIG. Folders come from the `projects` keys of each account's `.claude.json`, sorted by the mtime of `<config dir>/projects/<path with non-alphanumerics as '-'>` (where the transcripts live). `project_roots` stays as an optional extra.
6. ONE COMMAND. `cm up` starts `python -m cmgr serve` typed into a detached tmux/psmux session `cm` (so a crash stays readable with `tmux attach -t cm`). It is idempotent, and `--restart` is for after `git pull`. `cm down` sends ^C, then kills the session (Windows does not kill a pane's child processes). Verified through psmux. `cm doctor` lists the other machines with hints (cm not running / older version there).
7. BIND FAILURES. An address whose port is taken is skipped with a warning; the server exits only if nothing could be bound. `tailscale ip -4` output is validated as an IPv4 address (when logged out it prints a sentence).
8. PREFS SYNC. Since any machine's page can be opened, Perplexity thread URLs are written to every reachable machine (`/api/prefs`) and merged with this machine's values first.
9. TESTS. 41 pass on Windows (Python 3.13) and WSL Ubuntu 24.04 (Python 3.12). New: Authorizer rules, discovery against a real HTTP peer, Tailscale status filtering, whois caching, projects from history, the Remote Control link, prefs written to peers. The alias parser now converts PowerShell backslashes on Linux (found by the WSL run).
10. NOT VERIFIED. A real cross-machine request through the new auth, because the only machines available here (this PC and its WSL node) cannot reach each other over Tailscale TCP; the decision logic was checked against real whois data. Old configs from `cm init` (with `labpc` / `winbox`) should be deleted on rudy and computenode-01.

## D-002  [ACCOUNTS, v0.1.1] Accounts are labelled by the user's own shell aliases and merged across machines by account id; Linux tmux separator bug fixed before first deploy   [4 machines: 1 Windows (psmux) + 3 Ubuntu 22.04/24.04; aliases differ per PC, claude-b is the same everywhere]  2026-10-25

1. CONTEXT. Accounts are reached through per-PC aliases. `claude-b` is the same on every PC, and some names point at the same account (for example `claude-rudra` and `claude`). On Windows `claude-b` is a PowerShell function that sets `$env:CLAUDE_CONFIG_DIR` to `~/.claude-b` and restores it afterwards.
2. DISCOVERY (`cmgr/aliases.py`). Each agent reads, without executing, `~/.bashrc`, `~/.bash_aliases`, `~/.bash_profile`, `~/.profile`, `~/.zshrc`, `~/.zprofile` and the four PowerShell profile paths. A name counts when an alias or function calls `claude`. Its account dir is the first real `CLAUDE_CONFIG_DIR` it assigns (later restore lines such as `= $prev` are ignored), or the default `~/.claude` if it assigns none. Dirs reached only through an alias are included even when they are not named `~/.claude-*`.
3. LABELS AND MERGING. An account's label is its alias names joined with " / "; without aliases it is the dir name (`.claude-b` -> `claude-b`). The hub merges usage entries by accountUuid (falling back to email), unions the names across machines, and keeps the most recently fetched numbers. The email is shown under the label.
4. BUG FOUND IN WSL (Ubuntu 24.04, tmux 3.4) AND FIXED. `list-panes -F` used the control character 0x1F as its field separator. Linux tmux escapes control characters in format output, so every line failed to parse and NO panes were listed. psmux does not escape them, so Windows hid the bug. The separator is now the printable `<|>`. Re-checked on real tmux: pane listing, bracketed multi-line paste, key sending, and the registry match (`cm-smoke:@0.%0` -> right account, status idle). A first-run "trust this folder?" dialog is detected as "needs you".
5. TESTS. 31 pass on Windows (Python 3.13) and in WSL Ubuntu 24.04 (Python 3.12), 4 of them new alias tests (bash alias / function shapes, the exact PowerShell function, grouping by dir).
6. NOT VERIFIED. The three Ubuntu PCs themselves: their shell files may define names in shapes the parser does not know. `cm doctor` lists each account with its label; if a name is missing there, add it under `accounts` in that PC's config.

## D-001  [ARCHITECTURE, v0.1 BUILT] Plan B chosen: one small stdlib-Python service per machine + a mobile-first web hub; no model calls anywhere   [Linux + Windows/psmux, Tailscale; no hooks installed into Claude Code settings]  2026-10-25

1. CHOICE. Out of A (terminal app over SSH), B (service per machine + web UI), C (B + embedded Perplexity in a desktop shell) and D (headless stream-json sessions), B was chosen. Mobile use was a requirement, so the UI is a single page that works on a phone over Tailscale.
2. ONE PROGRAM, TWO ROLES. `cm serve` on every machine exposes `/api/*` (its own tmux panes, accounts, usage, DECISIONS.md). On the machine with `"hub": true` the same process also serves the UI and `/hub/*`, which fans out to the peers. Python stdlib only (no pip installs on any machine).
3. DRIVING SESSIONS. Sessions stay ordinary interactive Claude Code inside tmux/psmux. Read = `capture-pane -p -e` polled about once a second and rendered from ANSI to HTML. Write = `load-buffer` + `paste-buffer -p` (bracketed paste, so multi-line prompts do not submit at the first newline) then `send-keys Enter`; special keys come from a fixed allow-list. No pty attach, because attaching a phone-sized client would shrink the desktop's tmux window. psmux reuses pane ids (%1) in every session, so targets are always `session:window.pane`.
4. ACCOUNT PER SESSION WITHOUT HOOKS. Claude Code writes `<config dir>/sessions/<pid>.json` with `"tmux": "<session>:@<window>.%<pane>"`, `status` (busy/idle), `sessionId`, `cwd`. Matching that against `list-panes` gives the account for every pane. Stale files are dropped by a pid liveness check (on Windows via OpenProcess, never os.kill(pid, 0), which would terminate the process). Status = screen heuristics (permission / question prompt -> "needs you", "esc to interrupt" or registry busy -> working) because hooks would have to be installed into every account's settings and some hook outputs are added to the model context.
5. USAGE. `GET https://api.anthropic.com/api/oauth/usage` with the account's own access token and `anthropic-beta: oauth-2025-04-20` (the call `/usage` makes; verified 2026-10-25 on both local accounts: returns `limits[]` with kind / percent / resets_at plus `five_hour` / `seven_day`). Zero tokens. Undocumented, so the parser accepts both shapes. The manager only READS the token Claude Code maintains and never refreshes it (rotating refresh tokens could log the CLI out); an expired token shows as an error until Claude Code runs on that account again. Polled at most every 3 minutes per account, back-off on 429.
6. DECISIONS.md. Entries split on level-2 headings outside code fences, newest first (file order). Parsed: id (D-NNN), bracket tags, trailing date/time/zone, short title, size and a chars/4 token estimate. The first 25 bodies ship with the list, older bodies load on selection. Actions: copy, insert into the prompt at the cursor, copy + open the project's Perplexity thread (one thread URL per project name, stored on the hub).
7. PERPLEXITY. No API can read or write existing Perplexity threads, so integration is clipboard + deep link. An embedded Perplexity view (plan C) is the upgrade path if wanted later.
8. SECURITY. Shared bearer token on every machine (constant-time compare), listening only on the Tailscale IP and 127.0.0.1 by default. Clipboard API and system notifications need HTTPS, which `tailscale serve` provides; there is an execCommand fallback for copy.
9. NOT DONE / OPEN. No kill-session button (exit through the prompt instead). No raw per-keystroke typing mode, only the key bar plus the composer. The status heuristics depend on Claude Code's screen text and may need updating when its UI changes.
